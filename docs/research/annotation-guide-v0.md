# 巴西／圣保罗州法律研究标注指南 v0（草案）

> 版本：`v0-draft`
> 用途：受控研究和内部回归集构建
> 状态：未经巴西执业律师认证；不得用于向客户提供法律意见或自动作出决定

本指南把标注工作变成可复核的证据记录。它允许开展小规模、有监督的试点，但仍是 v0 草案：试点中发现的歧义必须进入变更日志，经负责人批准后才能形成新版本；不得静默改变已经完成的标签。

## 1. 角色和基本原则

每个条目由 `A1`、`A2` 两名标注者独立完成，`ADJ` 仲裁者处理差异，`DATA_LEAD` 负责批次冻结、抽检与版本变更。`ADJ` 不得是该条目的 A1 或 A2；若仲裁者存在利益冲突，应改派另一人。

执行时遵守六条原则：只使用批准来源；先记证据再下标签；不从标题或摘要推断正文；不把当前文本倒推到历史时点；不确定时显式标注而非猜测；所有可影响结论的变更均须留痕。

## 2. 术语

| 术语 | 操作定义 |
|---|---|
| 官方一手来源 | 由制定、发布或依法保管该规范的机关提供的公报、法规正文、法令页、判决或正式数据库记录 |
| 官方辅助来源 | 官方机关提供但不是规范正文的指南、表单、清单、FAQ 或流程说明；可证明行政要求，不能替代其声称引用的法条 |
| 二手来源 | 商业数据库、博客、论文或评论；只可作检索线索，不能作为规则卡的唯一规范依据 |
| 命题 | 待判断是否由证据支持的一条最小陈述；不得把多个可分别真假的条件合成一条 |
| 证据片段 | 支持某一命题所必需的最短连续原文，连同精确定位、来源和访问时间 |
| 时间截面 | 命题欲回答的具体日期或期间；缺少时间截面时不得判断“当时有效” |
| 修法关系 | `amends`（修改）、`revokes`（废止）、`suspends`（暂停）、`restores`（恢复）、`regulates`（施行／细化）或 `cites`（仅引用） |
| 规则卡 | 把法源命题结构化为适用范围、要件、例外、后果、所需事实和证据的临时记录 |
| 关键错误 | 会改变适用法源、时间效力、要件、例外、法律后果或人工升级决定的错误 |
| 未知 | 已按规定检索仍无充分证据；不是“否”或“不适用”的同义词 |

## 3. 标注对象与最小字段

### 3.1 法源记录 `LegalSourceRecord`

必填：`source_id`、完整标题、机关、法域、文种、编号／日期、官方 URL、访问时间（含时区）、文件或页面哈希、语言、来源等级、时间状态、状态证据和标注者。

### 3.2 条款证据 `ProvisionEvidence`

必填：`source_id`、条／款／项或页码定位、最小原文片段、规范化转写（如有）、命题、支持标签、时间截面、原文语言、证据哈希。扫描件 OCR 文本必须同时保留页码；不可辨识处写 `[ilegível]`，不得补写猜测内容。

### 3.3 修法／效力关系 `TemporalRelation`

必填：起点法源、终点法源、关系标签、受影响条款、发生／生效日期、证据片段、官方 URL、置信度与说明。一条关系只表达一个动作；“更新至某法”不能自动拆成具体条款关系。

### 3.4 临时规则卡 `RuleCard`

必填：`rule_id`、能力包、适用法域／活动／时间、最小命题、要件列表、例外、后果、所需事实字段、每一要件对应的 `ProvisionEvidence`、生产轨道、状态 `provisional`、不确定性和人工升级条件。找不到证据的字段保持未知，不得为了表格完整而推断。

### 3.5 测试案例 `ScenarioCase`

必填：合成／去标识化来源、事实时间、事实字段及出处、预期标签、适用规则卡版本、理由和人工复核状态。真实客户或个人材料未经书面批准和专门数据处理安排不得进入标注集。

## 4. 标签字典

### 4.1 证据对命题的支持

| 标签 | 使用条件 |
|---|---|
| `SUPPORTED` | 官方证据在指定时间截面完整支持命题的每个组成部分 |
| `PARTIAL` | 只支持部分命题；必须指出未获支持的部分 |
| `NOT_SUPPORTED` | 已定位的证据与命题不一致，或命题错误转述证据；必须说明差异 |
| `INSUFFICIENT_EVIDENCE` | 完成最低检索仍无法判断，或关键页面／附件不可得 |
| `CONFLICT` | 两项可接受证据在同一时间截面给出不能同时成立的结果，且无法按效力位阶／日期直接消解 |
| `OUT_OF_SCOPE` | 不属于本批次预先冻结的法域、活动、议题或时间范围 |

### 4.2 时间状态

只能选择 `IN_FORCE`、`AMENDED`、`REVOKED`、`SUSPENDED`、`RESTORED` 或 `UNKNOWN`。`AMENDED` 表示原文至少一部分被修改，不等于整部法令失效。没有直接官方证据时选择 `UNKNOWN`。

### 4.3 规则卡处置

- `INCLUDE_PROVISIONAL`：字段完整、证据达到最低要求，但尚未经认证；
- `REVISE`：命题可修正，需退回修改；
- `HOLD`：来源、效力或冲突尚未解决，禁止进入可用规则集；
- `EXCLUDE`：明确超范围、重复或不满足来源要求；
- `ESCALATE`：可能影响关键结论且指南不能决定，交由具备相应资质的专家。

## 5. 纳入、排除与最低检索

### 5.1 纳入

条目同时满足以下条件才可进入批次：属于冻结的圣保罗州／巴西法域和新能源绿地设厂议题；能访问并哈希保存官方一手或适用的官方辅助来源；能精确定位证据；有明确时间截面；不含未经批准的个人或客户机密信息。

### 5.2 排除或暂停

以下情形标记 `EXCLUDE` 或 `HOLD`：只有二手摘要；URL 指向搜索结果而非具体材料；条款／附件无法定位；文本疑似损坏或 OCR 关键字段不可辨识；命题跨多个法域／时间却不可拆分；存在未处理利益冲突；需要给出具体项目的法律意见；来源许可或数据处理条件不清楚。

### 5.3 最低检索步骤

1. 在批准的官方域名或正式公报中检索法令标题、编号和日期。
2. 打开具体文档页，核对机关、法域、编号和正文，不以搜索摘要作证。
3. 检查页面可见的修订、废止、整合文本和附件链接，并记录访问时间。
4. 若命题涉及历史时点，检索该时点前后的修法文件；没有版本证据就标 `UNKNOWN`。
5. 保存精确定位和快照哈希。访问失败须记录错误类别、时间和重试次数，不得转成否定答案。

完成以上步骤仍无充分证据才可使用 `INSUFFICIENT_EVIDENCE`。标注者不得自行扩大到未批准的商业数据库；如需新来源，先提交来源审批。

## 6. 证据粒度和转写规则

- 一条证据片段原则上对应一条最小命题；不同条款分别记录。
- 片段必须包含完成语义所需的主句、条件、否定词及直接适用的例外；不得只摘对己方结论有利的半句。
- 精确定位优先级：条／款／项 > 附件／表格单元 > PDF 页码＋首尾词。HTML 没有稳定锚点时记录标题层级和首尾各 8–15 个词。
- 原文保持葡萄牙语。中文／英文释义只能放在独立字段，并标为非权威翻译；不得用译文替换原文证据。
- 允许规范化空白和断行，但不得静默改正数字、否定词、单位、日期或专名。OCR 修正必须保留原值、修正值和理由。
- 引用量只取完成核验所必需的最短范围；超长附件可记录相关页而不复制整份文档。

## 7. 有效期、修法与冲突

标注“现行”必须同时指明 `as_of` 日期和支持该状态的官方证据。整合文本只能证明其自身声明的更新日期；不能自动证明访问日仍然现行。修法文件应分别记录公布日、生效日和受影响条款。无法判断生效规则时标 `UNKNOWN` 并升级，不得默认公布即生效。

遇到冲突时按以下顺序处理：先确认是否为不同法域、议题或时间截面；再确认文本版本、效力位阶和是否存在明确修法关系；仍不能消解则标 `CONFLICT`，保留双方证据并提交仲裁。标注者不得以个人法律解释覆盖明确冲突。

司法或行政决定可能影响适用性时，必须记录决定本身、效力范围、日期和是否已有正式文本。新闻稿、庭审报道或未正式公布的决定不能独自支持确定性状态。

## 8. 不确定性和人工升级

每个关键字段填写置信度：`HIGH`（直接、清晰、官方证据）、`MEDIUM`（官方证据存在但需有限解释）、`LOW`（材料不完整或有多种合理解释）。`LOW` 不能进入 `INCLUDE_PROVISIONAL`，必须 `HOLD` 或 `ESCALATE`。

下列情况强制升级：法源真伪／权限不明；时间效力或修法范围不明；例外会改变结论；官方来源相互冲突；跨联邦／州／市权限；可能触发罚款、停工、许可拒绝或刑事责任；问题要求对真实项目给意见；个人数据、安全事件或利益冲突。升级记录包括问题、已查来源、不能决定的原因、风险和期望答复，不预填答案。

## 9. 双标注、一致性与仲裁

1. `DATA_LEAD` 冻结批次、指南版本和条目哈希，随机分配给 A1/A2。
2. A1/A2 独立工作；提交前不可看对方标签、理由或聊天记录。
3. 系统比较标签、时间状态、证据定位和规则卡字段。文字不同但语义相同仍须由机器或负责人明确归并，不能静默视为一致。
4. 无差异条目进入抽检；有差异条目交给 `ADJ`，仲裁者必须重新查看原始来源，不以多数票或资历直接决定。
5. `ADJ` 选择 A1、A2、合并修正或 `HOLD/ESCALATE`，并写一条可复核理由和证据。
6. 若差异源于指南缺口，记录 `GUIDE_GAP`；更新指南后，对同类已标条目回溯重标。

一致性按批次计算，而不是只报告总体“准确率”：分类标签用 Cohen's kappa；证据跨度用 token-level F1；引用定位／URL／法令编号用精确匹配；关键字段另报关键错误率。样本过小导致 kappa 不稳定时，同时报告原始一致率和每类混淆矩阵，不掩盖少数类。

## 10. 质量门槛（v0 受控试点）

以下是进入**内部受控试点数据集**的预注册门槛，不等于法律正确性认证：

| 指标 | 批次门槛 | 未达标动作 |
|---|---:|---|
| 双人独立标注覆盖率 | 100% | 阻断批次 |
| 必填证据／时间／来源字段完整率 | 100% | 退回补录 |
| 引用定位、官方 URL、法令编号精确一致率 | ≥ 98% | 全量复核受影响字段 |
| 分类标签 Cohen's kappa | ≥ 0.80 | 仲裁全量差异并新增训练轮 |
| 证据跨度 token-level F1 | ≥ 0.85 | 校准粒度并重标抽样失败类 |
| 仲裁后关键错误率 | 0% | 阻断批次并做根因分析 |
| 非关键字段抽检错误率 | ≤ 2% | 超阈值则扩大至全量复核 |
| `LOW` 置信度误入可用集 | 0 条 | 立即移出并检查同类规则 |

每批至少抽检 20% 且不少于 10 条；批次少于 10 条时全检。门槛失败不能用删除难例、合并标签或事后改阈值来“通过”。任何阈值调整只对下一冻结批次生效，并记录原因、批准人和版本。

## 11. 隐私、安全、保密与利益冲突

- 默认只处理公开官方材料及合成／去标识化案例；真实客户材料、身份证明、联系方式或其他个人数据不进入普通标注环境。
- 申请人和标注者数据遵循目的限定、最小化、访问控制和到期删除；保留期限及权利渠道由实际数据控制者在收集前公布。
- 只用批准账户、设备、存储和传输渠道。不得上传到公共生成式 AI、个人云盘、公开仓库或未经批准的翻译／OCR 服务。
- 不在标签、理由或文件名中写入无必要的姓名、邮箱、账号、密钥或客户身份。意外发现时停止处理并报告，不自行扩散或删除证据。
- 每批次前更新利益冲突声明。与条目相关的现任／既往客户、雇主、项目或经济利益必须申报；负责人决定回避、加强复核或退出，并记录理由。
- 离开项目时撤销访问权限；按书面保留计划删除本地副本并形成确认记录。

## 12. 批次交付与变更记录

每批交付：冻结清单及哈希、指南版本、A1/A2 原始标签、差异表、仲裁结果、质量指标、抽检记录、排除／升级清单、来源访问失败日志和利益冲突处置记录。禁止只保留仲裁后的“干净答案”。

指南变更记录至少包括：版本、日期、提出人、问题样例、旧规则、新规则、影响范围、回溯重标决定、批准人。v0 试点结束前，`DATA_LEAD` 应整理仍未解决的 `GUIDE_GAP`；只有在独立专业复核、质量门通过且治理责任明确后，才能另行决定是否升级版本或用途。
