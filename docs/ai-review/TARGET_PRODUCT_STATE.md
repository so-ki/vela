# Vela 目标产品状态与工程宪法

版本日期：2026-07-17
状态：受控试点目标；不是 GA 承诺

## 1. 要呈现的产品状态

评审演示应呈现一条完整、受约束的协查链：

1. 业务提交项目事实与材料，并知情确认自身事实责任。
2. 法务确认场景范围，系统冻结 Capability Pack、规则、语料、检索和输入哈希。
3. 系统生成确定性 checklist；零命中保留为研究缺口，不补写法律结论。
4. 材料进入六状态账本，业务事实具有来源 block 和版本，法律主张同时绑定 checklist、已确认事实和可定位法源。
5. 法务逐项确认主张；CoverageProof 明确分母、已覆盖、未覆盖和不可判定。
6. 只有通过 Answerability Gate 的结果才能标记为交付定稿；其他结果只能是受限草稿。
7. 中葡简报、Word/PDF 和审计包可追溯到冻结输入、规则/语料版本、法源定位、时点、人工决定和导出哈希。

当前代码实现到哪一步，必须以 [`../REQUIREMENTS_TRACEABILITY.md`](../REQUIREMENTS_TRACEABILITY.md) 为准；本节描述目标，不能反向证明已经完成。

## 2. 架构边界

### 平台机制层

- 材料六态及状态转换
- 事实来源、确认与版本纪律
- Claim 编译、拒答和人工确认
- Coverage 分母与证明
- 审计、并发控制、导出追踪和安全边界

### Capability Pack 知识层

- 法域、行业和项目动作
- 法源与规则卡内容
- 事实字段、术语映射、红旗和输出配置
- 认证状态与适用排除项

机制层不得包含 Brazil、CNAE、CETESB、LP/LI/LO 或 LexML 必然存在等假设。某字段是否真正通用拿不准时，默认留在包内。

## 3. 三条抽象纪律

1. **删除巴西测试：** 不读取正式巴西 manifest、规则和语料时，平台仍须能用非真实 fixture 完成成功与拒答路径。
2. **允许第二包不同：** 第二场景不适配时先各写各的并记录差异，不得为了维护现有抽象而弯曲法律事实。
3. **真实实例后再上提：** 第一次写具体，第二次允许重复，第三次才考虑稳定抽象。接口在第二包前允许破坏性调整。

## 4. 认识论与法律安全约束

- 相似度、LLM 输出和抓取成功均不能把来源升级为 `expert_verified`。
- `provisional` 命中可进入人工审查队列，但不能自动成为 `supported` Claim。
- 零命中不等于不存在要求；系统必须明确拒答或标记缺口。
- “active source version”不等于已发布到正式 corpus，也不等于唯一现行法版本。
- 工程验收只证明控制按设计运行，不证明法律完整性、正确性、时点有效性或个案适用。
- 任何模型只能做候选提取、离线评测或红队，不得作为法律真值裁判。

## 5. 当前阶段非目标

- 不宣称覆盖全拉美、所有行业或实时完整法律数据库。
- 不在没有 gold set 时用 embedding 替换确定性检索。
- 不抓取或复制未获授权的 Jusbrasil 内容。
- 不允许第三方 LLM 在生产默认外发客户材料。
- 不把单客户单实例 RC 描述成多租户 SaaS。
- 不把测试 fixture 的 `expert_verified` 状态带入生产 Registry。

## 6. 完成的证据等级

| 等级 | 可以证明什么 | 不能证明什么 |
|---|---|---|
| 单元/集成测试 | 状态、权限、哈希、拒答和事务规则按样例运行 | 法律内容正确 |
| 删除巴西测试 | 核心路径没有依赖正式巴西制品 | 已支持第二国家 |
| 专家签核 | 指定来源/规则在指定时点和范围内经具名专家复核 | 永久有效或全量覆盖 |
| 真实客户 UAT | 指定部署与工作流可被该客户使用 | 通用市场适配 |
| 远端 CI/生产烟测 | 该提交的构建、迁移、镜像和黄金路径通过 | 客户环境已经部署 |

## 7. 技术候选的采用规则

GitHub 项目和论文用于提出可证伪实验，不用于替代证据：

- BGE-M3、Qwen3-Embedding 与 pgvector：只有在冻结的中葡西 gold query 上显著超过关键词基线，且错误高置信命中、延迟、资源、许可证和 SBOM 均通过，才可进入生产设计。
- Docling 与 Tesseract：必须保留页码、bbox、charspan、版本、原图/文本哈希和人工确认，报告 CER 与关键锚点遗漏率。
- RAGChecker、RefChecker 与 LegalBench-RAG：只用于 claim/retrieval 诊断和评测结构；最终法律 verdict 仍由确定性门禁与具名人工复核产生。

详细链接和退出条件见 [`../decisions/2026-07-17-evidence-retrieval-ocr-roadmap.md`](../decisions/2026-07-17-evidence-retrieval-ocr-roadmap.md)。
