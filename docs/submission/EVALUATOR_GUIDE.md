# Vela 评委操作说明

星瀚杯复赛最终提交版 · 建议独立测试时长 10–15 分钟  
案例：Aurora 储能系统集成工厂（虚构测试案例）

> Vela 是面向中国企业法务的拉美投资前合规协查过程保证平台。当前完成端到端验证的首个 Capability Pack 为“巴西 · 圣保罗州 · 新能源制造 · 绿地设厂”，环境许可是当前研究最深入的维度。

## 1. 先读边界

- Aurora 的企业、业务参数和材料均为虚构测试数据，不含真实客户数据，不构成正式法律意见。
- 正式结果来自真实 API，不是前端固定返回。
- 所有法律内容为 `provisional`。
- 律师认证、客户 UAT、客户生产部署和正式 Release 均为 `blocked_external`。
- `blocked_external` 是预期的外部证据边界，不是系统失败。
- 当前不声称完整覆盖拉美、全巴西、市级规则或实时完整更新。

## 2. 启动（约 1–2 分钟）

在终端执行：

```bash
cd "/Users/kys/Documents/vela for/vela-platform" && ./scripts/start_competition.sh
```

等待终端显示服务就绪。实际地址：

- 前端：`http://127.0.0.1:5180`
- 后端：`http://127.0.0.1:8010`

建议使用最新版桌面端 Chrome 或 Edge。若端口已被占用，启动脚本会拒绝复用未知服务；请释放端口后重试。

## 4. 第一部分：业务角色（约 4–5 分钟）

1. **登录业务账号（约 30 秒）**  
   在 `http://127.0.0.1:5180` 登录 `biz@demo.vela`。应自动进入“Aurora 项目材料与补件中心”。

2. **查看项目材料（约 30 秒）**  
   在“项目材料”确认能看到 Aurora 基础材料及处理状态。

3. **确认一项业务事实（约 45 秒）**  
   在“事实确认”选择任一已有事实；保持原值或作合理更正，点击“确认事实”。

4. **查看三项待补充信息（约 45 秒）**  
   核对三项标题：最终场址或选址状态、危险品最大库存、主要生产设备及活动分类。

5. **上传补充事实单（约 45 秒）**  
   上传 `docs/submission/AURORA_SUPPLEMENT_FACT.txt`。该文件只含虚构业务事实，不含法律结论。

6. **提交法务（约 20 秒）**  
   点击“提交法务”。

7. **核对进度状态（约 20 秒）**  
   页面应显示“已补充，等待法务复核”。

**业务角色通过表现**：只需完成事实和补件操作；页面不要求业务理解 ResearchItem、Claim、CoverageProof、法律研究、法源匹配分数或交付 Gate 内部结构。

## 5. 第二部分：法务角色（约 6–8 分钟）

1. **切换账号（约 45 秒）**  
   退出业务账号，在同一 `5180` 端口登录 `legal@demo.vela`。应直接进入 Aurora 法务工作台，无需寻找项目 ID 或手工拼接 URL。

2. **项目总览（约 40 秒）**  
   确认虚构案例、当前 Pack、环境许可研究重点、真实 API 说明和版本身份。

3. **材料与事实（约 45 秒）**  
   核对基础材料、补充材料和业务确认状态。

4. **固定 30 项（约 40 秒）**  
   核对 Pack 固定调查分母为 30。它表示 30 个调查清单事项，不是 30 张规则卡或 30 条法律结论。

<!-- PAGEBREAK -->

5. **法律研究（约 50 秒）**  
   查看 ResearchItem、来源与缺口。法律内容应标注为 `provisional`。

6. **Claim 与缺口（约 50 秒）**  
   核对 Claim 来自法务研究与草稿；未解决事项仍以缺口或未覆盖状态保留。

7. **CoverageProof 0.2（约 50 秒）**  
   核对 `schema_version=0.2`、`pack_total=30`、Scope 内处置与 out-of-scope 计数。Proof 表示过程与计数可复核，不代表法律判断正确。

8. **Gate 与交付中心（约 50 秒）**  
   查看事实或证据不足时的拒绝或受限状态。确认律师认证、客户 UAT、客户生产部署和正式 Release 均为 `blocked_external`；不得将该状态解释为系统失败。

9. **审计记录（约 40 秒）**  
   核对材料、事实、业务提交、研究、Claim、CoverageProof、Gate 和交付状态事件的操作者、时间与对象。

**法务角色通过表现**：八页工作台顺序完整；正式结果来自真实 API；业务补件进入同一 Aurora 项目；法律内容与外部批准边界标注准确。

## 6. 评委核对表

| 核对项 | 通过表现 |
|---|---|
| 单产品角色分流 | 两个账号均使用 `5180`，按角色进入业务中心或法务工作台 |
| 虚构案例边界 | 明确不含真实客户数据、不构成正式法律意见 |
| 三项补件 | 场址状态、危险品最大库存、主要设备及活动分类均出现 |
| 固定分母 | 30 个调查清单事项保持可见，Scope 不隐藏分母 |
| 过程拒绝 | 事实或证据不足时 Gate 拒绝或限制，不猜测答案 |
| 法律状态 | 法律内容为 `provisional` |
| 外部状态 | 四类外部环节为 `blocked_external` |
| 审计 | 操作者、时间、对象、版本与状态变化可核对 |

## 7. 常见情况

- 页面未自动进入对应角色入口：先退出账号，再从 `http://127.0.0.1:5180` 重新登录；不要手工拼接其他项目 URL。
- 上传失败：确认选择 `.txt` 文件，且文件未被其他程序锁定。
- `8010` 或 `5180` 已占用：结束占用端口的本地进程后重新运行比赛启动脚本。
- `blocked_external`：这是预期安全边界；不要上传虚构律师、UAT、部署或 Release 证据。
- 检查完成：退出账号，在运行启动脚本的终端按 `Ctrl+C`。

评委无需进入旧 Dashboard、寻找项目 ID、手工拼接 URL、进入 RC0，或在业务端查看法律研究内部字段。
