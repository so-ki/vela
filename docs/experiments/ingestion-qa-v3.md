# 实验④：官方法规 PDF 摄取锚点遗漏率 v3

## 结论

2026-07-17 对冻结的 10 份 AL-SP 官方文本、30 个经源文本验证的锚点实测：`30/30` 命中，锚点遗漏率 `0%`，低于预注册上限 `5%`。因此只支持以下窄结论：**对本冻结样本，现有 PDF 安全检查与文本抽取链路保持了人工标注锚点的相对一致性。**

不能由此声称逐字符准确、全文完整、扫描件 OCR 可用、复杂表格可用、法规现行有效或法律结论正确。样本中只有 1 份是 AL-SP 原生 PDF；其余 9 份是把官方 HTML 通过固定 Playwright Chromium 打印成 PDF，来源类型在逐条结果中明确区分。

## 方法与失效保护

- 样本、顺序和 5% 阈值沿用 v1/v2；v3 只修正 3 个经源页面人工核对的前导零日期锚点。
- 对 9 份 HTML 来源，运行器先在浏览器捕获的官方正文中寻找全部锚点。任一锚点在源文本中不存在，整次实验阻断，不计算遗漏率。
- 对 1 份原生 PDF 和 9 份实验 PDF 均执行平台实际的 25 MiB 限制、PDF 主动内容检查、250 页限制及 `pypdf` 文本抽取。
- 归一化只折叠大小写、重音、葡语序数标记、标点和空白；不采用语义相似度替代原文命中。
- 官方请求、渲染或解析错误均阻断结论；PDF 和法规全文只存在于权限为 `0600` 的临时目录，结果只保留哈希和计数。

首次运行还暴露并修复了一个生产缺陷：旧安全检查用字节子串识别 `/JS`、`/AA` 等 PDF 主动内容，导致普通 Chromium PDF 名称前缀被误报。当前实现按完整 PDF name token 比较，并覆盖 `#xx` 转义绕过测试；这不等同于杀毒扫描。
