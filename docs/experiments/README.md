## 实验① 州级元数据完备率

- **问题**：LexML 对首包目标法规（联邦＋圣保罗州）的 URN 解析、元数据与整合文本可得性到底有多完备？决定 Citator v1 的范围承诺。
- **方法**：对首包 30 条目标法规逐条查 LexML SRU API，记录四项：URN 可解析 / 元数据记录存在 / 修订关系（legislationChanges 或等价事件）可得 / 整合文本链接可达。输出覆盖率表。
- **脚本**：`backend/scripts/experiment01_state_metadata_coverage.py`（支持 `--offline` 用缓存 fixture 重放）。
- **判据（2026-07-18 预登记，先于运行写死）**：
  - 州级（SP）条目"URN 可解析且元数据存在"覆盖率 **≥ 70%** → Citator v1 承诺含州级；
  - **< 70%** → Citator v1 仅承诺联邦级，州级标注"人工核对"；
  - "修订关系可得"覆盖率单独报告，**不用于**本判据（只用于 A 层承诺措辞）。
- **状态**：已登记，待运行。结果文件：`docs/experiments/results/exp01_result.md`（由脚本生成，含运行时间戳与原始响应缓存哈希）。

## 实验③ 规则卡双轨生产

- **问题**：同一组规则，"表单逆向轨"（从 CETESB 许可文件清单/申请表字段反推事实 schema）与"法条正向轨"（从 Lei 997/76 + Decreto 8.468/76 拆要件）产出的卡差异有多大？每张卡的真实工时是多少？
- **方法**：首批 10 张卡双轨各做一遍，逐卡记录工时与差异类型（要件粒度不同 / 事实字段缺口 / 例外遗漏 / 完全一致）。
- **记录表**：`docs/experiments/实验③_双轨规则卡工时记录.md`。
- **判据（预登记）**：本实验为测量型，无通过线；产出直接决定要件库生产方式（哪轨为主、哪轨为校验）。**差异类型分布本身就是实验数据**，不得只记结论不记差异。
- **状态**：已登记。首批卡见 `backend/app/packs/brazil_new_energy/rule_cards/`。

## 实验④ 摄入 QA 抽样

- **问题**：解析含修订注记的州级法规文本（如 Decreto 8.468/76 括号注记嵌正文）时误差率多高？决定 A 层承诺"相对快照一致"的前提是否成立及限定语怎么写。
- **方法**：抽 10–20 份含修订注记的法规文本，管线解析结果与人工逐条比对，产出误差率。
- **脚本**：`backend/scripts/experiment04_ingest_qa_sampling.py`（生成比对工作表；人工比对结果回填后计算误差率）。
- **判据（预登记）**：
  - 块级解析误差率 **≤ 5%** → A 层可承诺"与来源快照逐块一致"；
  - **> 5%** → A 层承诺降级为"与来源快照整体一致，块级定位仅供导航"，并把误差率写进技术诚实声明。
- **状态**：已登记，比对表生成后待人工回填。
